# 把经历写成高光卡

## 一件事怎么写

每张亮卡写这几样：

| 字段 | 写什么 | 例子（通用示例） |
|---|---|---|
| 项目 | 这件事是什么 | 学院公众号运营 |
| 哪个环节 | 你负责的那一段 | 选题、写稿 |
| 做了什么 | 具体动作 | 每周看后台数据，停掉打开率最低的栏目 |
| 数据结果 | 结果，有数字写数字 | 一学期关注从 2300 涨到 5100 |
| 短版 | 14 个字以内，首屏和逛一圈用 | 关注 2300 → 5100 |
| 出处 | 这条从哪来（只在「自己看」那份显示） | 用户原话 / 截图 / 链接 |

写法：
- **先对上卡，再写数字。** 先确认这件事能证明哪张卡，再把结果写具体。
- **没有数字也能写。** 写交付了什么、别人怎么评价、你自己看到的变化。小成果也是成果。不要让用户估一个数。
- **只负责其中一环，分两层写。** 第一层：我负责的那一环，做了什么、结果怎么样；第二层：我看懂的上下游，整件事是怎么跑通的。团队的结果写清楚是团队的，不写成个人的。
- **一张卡可以放好几件事。** 最多 4 件，最亮的放第一件；首屏、逛一圈用第一件。
- **用用户的话。** 能用原话就用原话，润色只改说法，不加用户没说过的事、平台、数字。
- **点亮之前过三问。** 是用户做的吗？有具体动作吗？有结果吗？缺一样就标 `unclear`（页面上是「待完善」），不硬点亮。
- **数字以截图为准。** 几处说法对不上（比如简历和后台截图不一样），列出来让用户挑，不自己取。
- **因果要用户确认。** 「改了什么、所以涨了多少」这种，用户确认是这么回事才写；只是先后发生的，分开写。
- **挑最能说明问题的证据。** 一项能力有好几个证据，先挑一两个给用户确认，不全堆上去。做成过一次的，不如一直在做的；自己说好的，不如别人认可的（复购、回头合作、升职、被推荐）。
- **用户不想放的写法，照删。** 比如频率、排名、跟同类比，用户说不要就不写。

## 用岗位的话写

写进页面的每一句，都像这个岗位的人写简历、做汇报那样说：
- 先说做成了什么、结果，再说怎么做的。
- 用这个岗位常用的说法。比如新媒体运营说冷启动、选题排期、用户痛点、转化；产品说需求调研、上线、迭代；销售说客户拓展、成交、复购。拿不准的，看第 2 题扒到的招聘要求是怎么写的。
- 不用口语（「都是自己来」「我提了改法」），也不用 AI 腔和套话（「赋能」「抓手」）。短句，带数字。
- 写完给用户看，哪句不像他会说的，照他说的改。

## 代表项目：一件事写一份完整的

最拿得出手的 3～5 件事（interview.md 第 4 题 4a），写成代表项目，放在最外层的 `projects` 里。每个只写一份完整的；能力卡不再各写一遍，用 `ref` 指过去，`angle` 写这张卡的角度。

| 字段 | 写什么 | 例子（通用示例） |
|---|---|---|
| `id` | 编号，英文或拼音，卡片用它指过来 | `gzh` |
| `kind` | 种类：`work` 作品（一篇文章、一条视频、一份设计）／`project` 项目（账号、活动、合作、一段工作）／`tool` 工具（自己做的 AI 工具、网站） | `project` |
| `name` | 项目名 | 学院公众号运营 |
| `result` | 一句成果，放在名字下面 | 一学期关注从 2300 涨到 5100 |
| `role` | 我负责 | 负责选题、写稿和排期，每周复盘后台数据 |
| `points` | 怎么做的，两到五条（作品写关键判断，工具写它能做什么） | 停掉打开率最低的栏目，换成问答体 |
| `quote` | 可选：一段关键文案或用户原话 | |
| `results` | 结果，一条一条写 | 关注 2300 → 5100 |
| `shots`／`links` | 截图、原作链接 | |
| `more` | 可选：详细过程，点开才看到 | |
| `source` | 出处，只在「自己看」那份显示 | 用户原话 + 后台截图 |

能力卡里指向代表项目，一件事这样写：

```json
{"ref": "gzh", "angle": "每周复盘后台数据，停掉打开率最低的栏目", "short": "关注 2300 → 5100"}
```

- `angle`：这张卡关心的那一面。一个项目撑好几张卡时，每张写自己那一面，别都抄一样的。
- `result` 可选：这张卡想强调的结果；不写就用项目的一句成果。
- 代表项目建议 3～6 个，最多 8 个。
- 页面上：作品、工具先放截图，再说怎么做的；项目先说怎么做的，截图放后面。项目页最下面列出「体现的能力」，点了能跳回卡片。一页版把代表项目放在最高光后面，每个只写一次；发给 HR 那份，后面的能力卡每件只留一行。

## 没有工作经历：从闪光时刻里提炼

1. 让用户把闪光时刻都列出来：学校、实习、兼职、社团、生活里的都算，每件写发生了什么、结果怎么样、当时什么感觉。
2. 按成就感从高到低排，最让用户兴奋的放前面。
3. 在最重要的几件里找共性：用到了什么技能、对什么感兴趣、是什么性格。
4. 把共性提成关键词，对到能力卡上。一件事可以同时点亮好几张卡（比如办一场读书会，能点亮活动策划、沟通协作）。

## 卡片的状态

| 状态 | 什么时候用 | 页面上 |
|---|---|---|
| `lit` 已点亮 | 有一件事撑得住，出处清楚 | 金色亮卡；HR 能看到 |
| `unclear` 做过但没写清 | 有这件事，缺「你负责哪块」或结果 | 半亮；只在自己看的版本里 |
| `weak` 证据不够 | 有这件事，缺截图、链接或细节 | 半亮；只在自己看的版本里 |
| `todo` 待补 | 没有沾边的事 | 灰卡＋小任务；只在自己看的版本里 |

个人背景区的卡加 `"fact": true`：学历、专业、证书只写事实，不写成高光（漏写了，生成时会自动补上）。

## 怎么排

- 亮卡里，越对岗位、成就感越强的越靠前，最高光的放第一张。
- 个人背景区排在最后。
- 不按时间排。

## 出处

每张亮卡都写出处：「用户原话」「截图」「链接」。AI 自己推断出来的内容，单独标「推断」，并在第 10 题让用户确认；用户不认的，删掉。

出处是给用户自己核对「AI 没编」用的，只在「自己看」那份显示。「发给HR」那份生成时去掉出处，页面上换成「截图 2 · 链接 1」这种标记。

## 写进 portfolio.json

```json
{
  "site": "小周的个人作品堡",
  "owner": "小周",
  "pronoun": "TA",
  "role": "新媒体运营",
  "style": "晨雾紫",
  "jdCount": 10,
  "tagline": "一句话介绍：让人一眼看出你配这个岗位。",
  "about": "一小段自我介绍：你是谁、做成过什么、想去什么岗位。",
  "aboutSource": "用户原话",
  "links": [{"label": "作品集", "url": "https://…"}],
  "top": ["内容策划与写作", "账号从 0 到 1", "活动策划"],
  "regions": [
    {
      "name": "技能",
      "cards": [
        {
          "name": "内容策划与写作",
          "state": "lit",
          "need": 9,
          "weight": 9,
          "highlight": {
            "project": "学院公众号运营",
            "step": "选题、写稿",
            "did": "每周看后台数据，停掉打开率最低的栏目",
            "result": "一学期关注从 2300 涨到 5100",
            "short": "关注 2300 → 5100",
            "source": "用户原话 + 后台截图",
            "shots": ["shots/公众号后台.png"],
            "links": [{"label": "看公众号", "url": "https://…"}]
          }
        },
        {"name": "数据复盘", "state": "todo", "need": 8, "weight": 8, "task": "拆 3 个同类账号近 30 天的数据，做一页表，写 3 条结论。", "taskPoints": 30}
      ]
    }
  ]
}
```

- `style`：风格，四套里选一套：晨雾紫 / 奶油杏 / 薄荷绿 / 海盐蓝，采访第 9 题起名字时选。没写就是晨雾紫。区域的颜色跟着风格走，不能单独改。
- `tagline`：一句话介绍，首屏第一句；`about`：一小段自我介绍，点「关于TA」能看到（「TA」跟着 `pronoun` 变；「自己看」那份这个入口叫「宿主档案」，跟系统版的说法一致）。都在采访第 9 题拟好、用户确认过。
- `links`（最外层）：这个人的链接，比如作品集、主页，可选。
- `top`：最高光三条，写卡名，按用户挑的顺序。没写或不够三条，生成时按「几家要」补齐（个人资源、个人背景两区排后面），脚本会打出来是哪三张，要告诉用户。
- `short`：短版，14 个字以内，写在那件事（`highlight`，或者 `highlights` 第一件）里面，不写在卡上；首屏和逛一圈用，不写就用数据结果全文。
- 一张卡好几件事：把 `highlight` 换成 `highlights` 列表（最多 4 件，最亮的放第一），每件的写法跟上面一样。
- `need`：这张卡「几家要」（实际读到 `jdCount` 家里，有几家要）。个人资源、个人背景两区的卡是用户自己带来的，不写 `need`。`need` 写阿拉伯数字，不能比 `jdCount` 大。`weight` 只管排序；页面上的「几家要」只看 `need`，没写就不标，不拿 `weight` 顶。
- `jdCount`（最外层）：实际读到几家招聘要求，凑不够 10 家就写实际的数。
- `contact`（最外层，可选）：联系方式默认不放；用户想放，只建议邮箱。
- `pronoun`（最外层）：页面上称呼这个人用的字：她 / 他 / TA。拿不准就写 TA，不要猜。
- `theme`（最外层，可选）：开场是清晨 / 黄昏 / 星夜（`dawn` / `dusk` / `night`），不写就是清晨。
- `footnote`（最外层，可选）：左下角和一页版页脚那行小字，不写就显示「个人作品堡 · 用 AI 做的」。示例数据里那句「示例数据 · 人物和经历都是编的」只给示例用，别带进用户的数据。
- `shots` 写图片在用户电脑上的路径（相对 portfolio.json 所在的文件夹），生成时会变成内嵌图片：同一张图只存一份，长边超过 2000 像素的自动缩小（电脑上有 PIL，或者是 Mac），放在页面最后。每张卡先放最能说明问题的一张；单张最好 0.6 MB 以内，加起来 4 MB 以内。
- `projects`（最外层，可选）：代表项目，写法见上面「代表项目」。
- `links` 只收 http/https 开头的链接。
- 最多 6 个区域，每个区域建议不超过 4 张卡。
- 完整示例见 `examples/portfolio.example.json`（示例人物和经历都是编的）。
