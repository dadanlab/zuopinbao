# 没亮的卡：怎么补问，怎么派小任务

## 先补问（最多 3 张卡）

挑「10 家里出现次数最多、还没亮」的卡，一题问一张，按这四种问（话术见 interview.md 第 5～7 题）：

1. 直接做过吗？
2. 间接碰过吗？比如帮别人做过其中一部分。
3. 有相关的吗？比如课程作业、比赛里用到过。
4. 自学过吗？比如看教程跟着练过。

问出来了，按 evidence.md 写成高光；只问出一半的，标成 `unclear` 或 `weak`。问两三次还是没有，就别再追了，派小任务。

## 小任务怎么定

缺哪个补哪个。一个好任务要同时满足：

- **岗位要的**：直接对着这张卡。
- **能拿出来看**：做完有截图、链接或文档。
- **两周内做得完**：不派「去考个证」「去找份实习」这种做不完的。

写清楚三件事：做什么、做到什么程度、做完交什么。

## 例子（通用示例，按岗位改）

| 区域 · 卡 | 小任务 |
|---|---|
| 技能 · 数据复盘 | 拆 3 个同类账号近 30 天的数据，做一页表，写 3 条结论：哪类内容涨得最快、为什么。 |
| 经验 · 活动策划 | 给社团、朋友或自己的账号策划一次小活动，写方案，办完写复盘：来了多少人、哪里没做好。 |
| 行业认知 · 公司研究 | 挑 1 家想去的公司，按「招聘要求背后，公司想解决什么问题」写一页分析。 |
| 个人资源 · 作品 | 开一个跟岗位相关的账号，两周发 3 篇作品，截图数据。 |
| 软技能 · 协作 | 写一次跟人配合把事做成的复盘：对接了谁、卡在哪、最后怎么推下去的。 |

## 做完以后

用户把素材发来，说「点亮【卡名】」：按 evidence.md 写成高光 → 给用户确认 → 重新生成 → 再发布一次。没做完的不点亮，也不写进发给 HR 的那一份。
