# 没亮的卡：怎么补问，怎么派小任务

## 先找，再问

补问之前，先在已经收到的材料和代表项目里找跟这张卡沾边的：沾边的就往匹配度上靠，找到了跟用户确认一句就点亮（interview.md 第 4 题 4b）。后来学会的能力也算，前提是用户能讲清怎么做、能做出来，结果照实写。找不到，再按下面问。

## 先补问（最多 3 张卡）

挑「10 家里出现次数最多、还没亮」的卡，一题问一张，按这四种问（话术见 interview.md 第 5～7 题）：

1. 直接做过吗？
2. 间接碰过吗？比如帮别人做过其中一部分。
3. 有相关的吗？比如课程项目、比赛里用到过。
4. 自学过吗？比如看教程跟着练过。

问出来了，按 evidence.md 写成高光；只问出一半的，标成 `unclear` 或 `weak`。问两三次还是没有，就别再追了，派小任务。

## 小任务怎么定

缺哪个补哪个。派之前先做三件事：

1. **看招聘原话。** 这张卡在招聘要求里具体怎么写的（jd-analysis.md 第 4 步摘的），任务就对着它定。
2. **查权威做法。** 先看平台官方的说明，再看行业通用的做法，记下出处，派任务时一起给用户。
3. **用他手上现有的东西做。** 有现成的（自己的账号、工作里的后台和资料），就用现成的；没有的，你帮他找能公开拿到的材料（公开的数据、案例、报告、评论），教他怎么分析，让他做出一份东西。⛔ 小任务不能牵出一件难事：不让他为了这张卡去开账号、找实习、做产品、拉客户、考证。

一个好任务要同时满足：

- **岗位要的**：直接对着这张卡。
- **能拿出来看**：做完有截图、链接或文档。
- **两周内做得完**：一个小任务不能牵出一件大事（开账号、找实习、做产品、拉客户、考证这种）。

写清楚三件事：做什么、做到什么程度、做完交什么。

## 例子（通用示例，按岗位改）

| 区域 · 卡 | 小任务 |
|---|---|
| 技能 · 数据复盘 | 手上有数据的（自己账号的后台、工作里的报表）：挑最近一段，找出最好和最差的，写 3 条原因。没有的：你帮他找公开能看到的数据（比如同类账号的公开数据、行业公开的报告），教他怎么比，他做出一张表，写 3 条原因。一周能做完。 |
| 经验 · 活动策划 | 给社团、朋友或自己的账号策划一次小活动，写方案，办完写复盘：来了多少人、哪里没做好。 |
| 行业认知 · 公司研究 | 挑 1 家想去的公司，按「招聘要求背后，公司想解决什么问题」写一页分析。 |
| 行业认知 · 用户洞察 | 你帮他找同类内容下面的公开评论 30～50 条，教他按「遇到的难处、担心什么、想要什么」归类，他写一页结论：这群人最在意什么。 |
| 软技能 · 协作 | 写一次跟人配合把事做成的复盘：对接了谁、卡在哪、最后怎么推下去的。 |

## 做完以后

用户把素材发来，说「点亮【卡名】」：按 evidence.md 写成高光 → 给用户确认 → 重新生成 → 再发布一次。没做完的不点亮，也不写进发给 HR 的那一份。
